# 天気コンパス

複数ソースの天気予報から統合値とソース間のばらつきを表示します。日本語 UI、スマートフォン対応、ライト・ダーク切替。実行時は HTML / CSS / JavaScript と JSON のみを使います。フレームワーク、API キー、ビルド、アプリケーションサーバーは不要です。

## API と対象データ

| ソース | エンドポイント | 取得内容 |
| --- | --- | --- |
| Open-Meteo | `https://api.open-meteo.com/v1/forecast` | `models=ecmwf_ifs025`、`gfs_seamless`、`icon_seamless`、`jma_seamless` を別々に取得 |
| MET Norway | `https://api.met.no/weatherapi/locationforecast/2.0/complete` | 通常のブラウザ fetch、気温・風・降水量・天気。確率は1時間値がある場合のみ |
| 気象庁 | `https://www.jma.go.jp/bosai/forecast/data/forecast/{office}.json` | 日別天気、降水確率、最高／最低気温。地点に地域コードを設定 |
| 都市検索 | `https://geocoding-api.open-meteo.com/v1/search` | 都市名から緯度・経度・タイムゾーンを取得 |
| 検証 | `https://archive-api.open-meteo.com/v1/archive` | 時間別の再解析値。観測を取り込んだ格子データで、地点の観測所実測値とは差があり得る |

API の利用条件・帰属表示・利用制限は各提供元を参照してください。Open-Meteo の無償提供には利用条件があります。モデルや地点、変数によって利用可能な期間と項目が異なります。画面の「—」は欠測です。ブラウザはネットワーク障害と CORS 拒否を区別できない場合があるため、該当時は共通の理由を表示します。取得は並列で、各リクエストは8秒で打ち切ります。成功レスポンスは開いているタブ内で20分間キャッシュします。

参考資料 [Open-Meteo Forecast](https://open-meteo.com/en/docs) · [Open-Meteo Historical](https://open-meteo.com/en/docs/historical-weather-api) · [MET Norway](https://api.met.no/weatherapi/locationforecast/2.0/documentation) · [気象庁の地域コード](https://www.jma.go.jp/bosai/common/const/area.json)

## GitHub Pages への公開

1. ZIP を解凍し、`index.html`、`styles.css`、全 JS、`sources/`、`mock/`、`.nojekyll` をリポジトリのルートへ配置してコミットします。
2. GitHub の **Settings → Pages** で **Deploy from a branch** を選び、対象ブランチの **/ (root)** を指定します。
3. Pages 設定に表示された HTTPS URL を開きます。アセットは相対参照なのでプロジェクトサイトのサブパスでも動作します。現在地を使う場合はブラウザで位置情報を許可します。

ローカルで開発確認する場合は、このディレクトリで `python3 -m http.server 8000` を実行し、`http://localhost:8000/` を開けます。ES モジュールと JSON の読み込みには HTTP(S) が必要です。

## 段階ごとの確認

1. **構成と API**  
   上の表と `config.js` で URL・モデル・地点・ソース ID を確認します。初期設定の `useMock` は `false` です。
2. **モックと統合**  
   `useMock: true` にして再読み込みするか、画面上の「モックで試す」を選びます。東京で6ソース、今日から7枚のカード、48時間グラフを確認します。グラフの項目を切り替え、赤い印の時刻をクリックすると、降水量に「割れ」が表示されます。スライダーで値・最大差・標準偏差を確認できます。日別カードを選ぶと比較表が日別になります。「大阪」を検索して地点切り替えも確認できます。
3. **Open-Meteo 実 API と失敗時の表示**  
   `useMock: false` に戻して Pages を再読み込みします。ブラウザの開発者ツールの Network で `/v1/forecast` が4件あり、各 `models` が異なることを確認します。各モデルの HTTP ステータスと JSON の `hourly` を確認し、画面の取得件数と照らし合わせます。失敗を再現するには `simulateFailures: ['ecmwf']` にして再読み込みします。ECMWF が理由付きでスキップされ、他の成功ソースで統合されます。同じ確認をモックでも再現できます。全件取得に失敗した場合は「モックで試す」で切り替えられます。確認後は `simulateFailures: []` に戻します。
4. **MET Norway と気象庁**  
   実APIモードの東京で MET Norway と気象庁のリクエストを確認します。ブロックされた場合はスキップ欄に理由が表示されます。日別比較表に気象庁の値、時間別比較表に欠測が表示されます。ロンドンでは気象庁が対象地域外になります。ブラウザの表示幅をスマートフォン相当にし、カードと表の横スクロール、配色切り替え、現在地と拒否時の表示を確認します。
5. **精度検証と重みの反映**  
   初回は「データ不足」を確認します。モックモードで「モック検証データを追加」を押すと2日分のサンプルが保存され、降水有無の順位・各 MAE・提案の重みが表示されます。「提案の重みを反映」でソース別比較表の重みが変わります。「設定の重みに戻す」で初期設定に戻ります。実API では同じ地点を数日以上開いて予報を蓄積し、再解析データが公開された後に「検証を更新」します。再読み込みしても同じブラウザ・同じ公開 URL で保存データを利用できます。モックの保存データと重みは実APIと別です。

モックでは固定の合成予報を現在の日付へ移動します。各地点で同じ合成データを使い、モックの日付・数値から実際の天候を判断することはできません。モックの都市検索は設定済み都市を検索します。

## 統合・信頼度・精度検証

- 時間別は UTC の同一時刻で揃え、地点のタイムゾーンで表示します。気温・風速・降水量は重み付き中央値、降水確率は重み付き平均、天気は共通6カテゴリの重み付き多数決。同票の場合はカテゴリ順で雷雨、雪、雨、霧、くもり、晴れの順に優先します。
- 日別は各ソースの最高／最低気温・最大時間降水確率・代表天気を先に求めて統合します。気象庁では発表された日別情報を使い、短期の6時間降水確率は日内最大値を代用します。MET Norway の6時間時系列は日別に使い、6時間降水量を1時間量に換算しません。
- 最大差と母標準偏差は各ソースを等しく数えます。最大差または標準偏差が `config.spread` の境界に達すると信頼度が下がります。天気は一致したカテゴリ数で判定し、コードの最大差と標準偏差は参考表示です。2ソース未満の項目は比較不足です。週間カードの信頼度は判定可能な項目のうち最も低い段階を表示します。「割れ」は 0.1 mm 以上と未満の予報が混在する時刻です。時間降水量が欠測の場合は天気カテゴリから降水の有無を補います。
- 取得時に、地点・ソース別の最新の時間別／日別予報と検証用スナップショットを `localStorage` に保存します。検証では各時刻の6〜24時間前に取得した最新予報を使用し、地点の前日から過去7暦日を集計します。検証用の古い時刻は次回取得時に整理します。
- 的中率は1時間降水量が 0.1 mm 以上かどうかの一致率です。MAE は気温、時間降水量、風速を別々に集計します。時刻の粒度を揃えられない気象庁の日別データは時間別ランキングの対象外です。ランキングは降水の照合が24件以上のソースに付きます。予報・照合値の欠測で件数はソースごとに異なります。
- 重みの提案は気温 MAE の逆数を平均1に正規化し、0.25〜3に制限します。気温の照合が24件以上あるソースが2つ以上で有効です。反映するまで現在の重みは維持されます。反映後は同じブラウザ・同じモードの全地点で使用します。

## 設定と拡張

- `config.js` の `sources[].weight` を変更して再読み込みします。初期値は全ソース `1.0` です。0 は統合から除外します。過去に反映した重みは画面の「設定の重みに戻す」で解除できます。
- `places` に緯度、経度、IANA タイムゾーンを追加し、`defaultPlace` に地点 ID を指定できます。日本地点で気象庁を利用するには `country: 'JP'` と `office`、`area`、`weekly` を設定し、気温にも対応する場合は `station` を指定します。初期設定は東京、大阪、札幌、福岡、名古屋、那覇です。検索・現在地で設定済み地点の近傍を選んだ場合は対応コードを使います。その他の国内地点はコードが設定されるまで気象庁だけスキップします。
- 同じ API のモデルを増やす場合は `sources` に一意の `id` と `model` を追加し、同名のモック JSON を用意します。別 API の場合は `sources/` にアダプタを追加し、`sources/index.js` の `adapters` と `config.js` に登録します。アダプタは `{ hourly, daily? }` を返し、時間別レコードを `{source, time, temp, precipProb, precipMm, windSpeed, weatherCode}` に揃えます。`time` は UTC Unix ミリ秒、数値欠測は `null`、風速は km/h、降水量は直前の1時間の mm です。日別レコードは `date` と必要な `min`、`max` 等を持ちます。
- URL は `sources[].baseUrl` で置き換えられます。気象庁の URL は `{office}` を展開します。将来プロキシを使う場合、同じクエリ・パスとレスポンス形式を維持してください。検索・履歴 URL も設定できます。
